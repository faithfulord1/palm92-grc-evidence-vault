## A repeatable work cycle
1. Pick one business question, for example whether a critical supplier has adequate recovery evidence.
2. Use official criteria and fictional data. Document scope, evidence and unknowns.
3. Build a small reproducible example and test decision boundaries.
4. Save code, worked case, results and limitations in a review branch.
5. Explain what YOU changed, tested and concluded.
6. Produce an original narrated demo and a LinkedIn post from that same work.
7. Obtain publication approval, then publish and retain the URL and feedback.

## Four work sessions, not a configured schedule
1. Supplier evidence: complete this lab, inspect findings, rehearse the video.
2. Audit evidence: inspect the existing Evidence Vault verifier and test evidence tampering with synthetic files; record results before claiming success.
3. Repository risk: inspect RepoGuard, review dependencies, permissions and evidence provenance; build one bounded demonstration.
4. Assemble the strongest two case studies into a profile README and portfolio page after checking claims and links.

For CISA study, keep original notes and audit workpapers showing objective, scope, criteria, evidence, test, finding, recommendation and follow-up. Use ISACA's current requirements and exam outline. Do not copy exam dumps or describe yourself as certified before certification is awarded.

## Reposting other people's work
Prefer sharing the creator's original link with your own useful commentary. For copied footage or adaptations, check permission and the content's licence; attribution alone is not permission. Software licence and media rights are separate. Keep a record of source URL, revision, licence, permissions, changes and asset rights. Clearly distinguish upstream work from your own contribution.

## Podcast claims to treat carefully
The supplied transcript is useful inspiration, not a verified product manual. Claims that every tool is free, a subscription cancellation always removes a website, or an AI assistant reads a repository continuously depend on the actual service and configuration. GitHub does not create continuous agents by itself. Store large final videos outside normal Git history; keep scripts and project files in Git. Private repositories still require suitable controls for confidential information.
